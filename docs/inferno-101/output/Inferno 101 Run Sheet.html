What Inferno does

0:40
Screen

Slide 2, What Inferno does

Say

FHIR implementation guides describe the rules systems need to follow. Inferno turns selected requirements from a guide into automated tests.

A test run can check a FHIR document or interact with a FHIR server. It gives you a repeatable result and the evidence behind that result.

These are community reference tests. They help you find implementation problems, but they do not provide certification or confer conformance status.

Choosing a test kit

0:40
Screen

Slide 3, Choosing a test kit

Say

Choose the test kit that matches what you built.

Use the AU Patient Summary kit when you have a patient summary Bundle, or a server that supplies or generates one.

Use the AU Core kit when you operate a FHIR server that another system will query. The test kit page lists the available versions, so select the version that matches your implementation.

A quick interface tour

1:05
Screen

Browser at https://inferno.hl7.org.au/test-kits, then open the prepared AU PS session as an interface example.

Prep

  • Use synthetic data only.
  • Open the test kit index and the prepared interface-tour session.
  • Set browser zoom so test names, Messages, and the session header are legible.

Actions

  • Show the available test kits and open one kit page.
  • Point out the version selector and session creation action without starting a new run.
  • Open the prepared session and identify its suite, groups, and individual tests.
  • Open one result and show its Messages tab.
  • Point to the session URL and Report button.

Say

The test kit index lists each kit and its supported versions. Choose the version that matches your implementation before creating a session.

A session holds one run and has its own URL. Its suite represents the guide version, with groups containing individual tests.

This prepared result only shows the interface. Open a test for its status and message. Server tests also show the HTTP request and response in Requests.

Keep the session URL when you ask for help. Another tester can open the same run and inspect the evidence. Download the report if you need a longer-lived record because public sessions may be removed.

Fallback

If the prepared session is unavailable, stay on the test kit page and use Slide 4 to explain the same workflow.

5

A useful first run

0:50
Screen

Slide 4, A useful first run

Say

For your first run, use synthetic test data and start with one small group. A whole suite is useful for a baseline, but it often produces more information than you need while fixing one problem.

Read the first failure before the results that depend on it. A skipped test usually means Inferno could not run the check because a prerequisite was missing.

Open Messages to understand the finding. For a server test, use Requests to inspect the HTTP evidence. Make one change, rerun the group, and confirm the result changed as expected.
